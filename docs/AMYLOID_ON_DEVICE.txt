Amyloid Candidates — On-Device Analysis

Default route: /tools/amyloid-inspector
No AMYLOID_API_URL, account, local Python installation, or analysis server is
required. Selecting files alone previews a single structure. Analyze On My Device
starts calculations in a dedicated module Web Worker. No coordinates, filenames,
confidence metadata, or results are uploaded.

CALCULATIONS
The unchanged pinned Amyloid Candidates package calculates common QC, geometry,
packing, energetics, and positive-reference warning gates. Progress observers wrap
component entry/return without altering arguments or returned scientific results.
The progress bar counts completed work within the CURRENT stage, not predicted
elapsed time. Setup and report packaging use an indeterminate bar. Descriptor
progress has six stages per input: parsing, QC, geometry, packing, energy, reports.
Alignment progress counts completed/skipped directed calls; clustering counts
finished construct groups. Failures remain visible. Elapsed time includes loading.

LIVE DIAGNOSTICS
The local run displays processed operations per minute, last-operation wall time,
a rolling mean of up to 20 operations, and an approximate time remaining for the
current calculation stage after three timing samples. Skips do not increase the
rate; failure/skip counts remain visible. Estimates exclude later stages and are
not completion guarantees. Completed-stage statistics freeze when that stage ends.

Python memory is allocated WebAssembly linear memory, read using the public
Pyodide PyBuffer.getBuffer API on a one-byte probe. Views are refreshed and released
for every sample to accommodate growth. The sampled peak is not total browser or
device memory: it excludes the independent MM-align runtime, MEMFS file storage,
JavaScript objects, and other page allocations. CPU utilization is not estimated.
https://pyodide.org/en/stable/usage/api/js-api.html#pyodide.ffi.PyBuffer.getBuffer

A resource PerformanceObserver in the worker counts only engine/runtime requests.
Transfer bytes use the browser's transferSize including its header-size estimate.
Average download rate is observed bytes divided by the span from the earliest
measured request start to the latest measured response end (overlap counted once).
It is not instantaneous bandwidth or a connection speed test. Zero-byte
cross-origin records are marked unmeasured because timing restrictions and cache
hits cannot be distinguished. Same-origin zero-transfer/nonzero-body records are
counted as local/cache responses. Unsupported APIs show unavailable metrics.
https://developer.mozilla.org/en-US/docs/Web/API/PerformanceResourceTiming/transferSize

Interface delay measures excess delay of a one-second main-thread timer; it is
not network latency. Sampling pauses while the document is hidden. Diagnostics
emit at most once per second, plus stage boundaries and the final snapshot.
Synchronous calculation steps can delay samples; their age is shown without
claiming that a busy worker has stalled. Telemetry does not reset job watchdogs.
All diagnostics stay in page memory, freeze on cancellation/completion, and reset
on a new run/selection. They are not sent to analytics or the analysis server.

For multiple files, Compare And Cluster Structures is enabled by default and can
be turned off. It uses:
- Package-normalized first-model C-alpha exports with sequential chain/residue IDs
  and coordinates at 0.001 angstrom, shared with the native worker.
- Groups with identical sorted normalized chain sequences and stoichiometry.
- MM-align compiled from the same pinned source as the native executable, with
  full scoring, no -fast approximation, self checks, both directions, explicit
  length-normalized TM scores, and validated alignment coverage/chain mapping.
- Distance = 1 - mean(forward minimum TM score, reverse minimum TM score).
  Missing/failed distances are never imputed. A failed comparison invalidates
  clustering for that group; successful individual reports remain downloadable.
- scikit-learn 1.8.0 HDBSCAN: precomputed distance, brute, EOM, epsilon 0, alpha 1,
  n_jobs 1, allow_single_cluster false. The UI min_samples excludes the point
  itself, matching the native pipeline convention; sklearn receives min_samples+1.
  Native server jobs retain contrib hdbscan 0.8.44. The browser backend, version,
  and effective settings are explicit in every group report. Despite matched
  conventions, ties/implementation differences may produce different partitions.
- Shared frozen feature transforms, ranking, medoids, support checks, and diversity
  selection. Missing confidence stays unavailable. Optional confidence CSV is
  validated identically to the server. No confidence is inferred from B-factors.

LIMITS AND LIFECYCLE
Up to 125 unique filenames, 10 MiB each, 100 MiB total; PDB/mmCIF, first model only,
20,000 normalized atoms and 32 polymer chains per structure. Confidence CSV <=64 KiB.
Default clustering: min_cluster_size 10, min_samples 3 (4 including self in sklearn).
Pools too small for the settings get unavailable clusters, not fabricated noise.
There can be at most 15,625 directed MM-align executions; comparable singleton groups
need none. Runtime and memory use depend on the device, structure, and batch size.
The pairwise workload grows quadratically. Desktop use is recommended for batches.
These are configured input safeguards, not measured browser capacity guarantees.
The selection summary shows the maximum comparison count before starting; the
progress bar uses the actual count after grouping. Smaller batches may still
exhaust memory on some devices. The cluster-size control allows 2-125 members,
and minimum samples allows 1-124 neighbors; scientific defaults remain unchanged.

Each MM-align invocation gets a fresh Emscripten instance to avoid cross-pair state.
Its memory may grow to 1 GiB; this is a ceiling, not an allocated amount or an
estimate for the whole browser job. Memory exhaustion can still stop a job.
Initialization inactivity timeout: three minutes. Each descriptor/report phase:
five minutes without a stage update. Each directed alignment: two minutes.
Cancel terminates the worker immediately and discards that run. Completion and
navigation also terminate it, freeing the runtime. Results live only in page
memory; download before leaving/reloading. Switching inspector modes retains the
active local run. No background continuation after closing the page is promised.

Browser assets: public/tools/amyloid-device/v1/.
Amyloid Candidates: 1c85221ea38ffbaa1695eeb0a2962997abf94563, unchanged public source.
MM-align/USalign: 23f14ffcf8647f2dc1c0e01043db3a7f3a661c28, unchanged public source.
Pyodide 314.0.8: https://cdn.jsdelivr.net/pyodide/v314.0.8/full/
NumPy 2.4.6, Biopython 1.87, FreeSASA 2.2.1; batch analysis additionally loads
pandas 3.0.2, scikit-learn 1.8.0, and SciPy 1.18.0 from this pinned release.
Dependencies are loaded with Pyodide integrity checks. The package, Python adapter,
shared pipeline archive, and MM-align assets have SHA-256 records in engine.json.
The Wasm module and its JS wrapper are verified before use. Build/source/license
records accompany the binary and downloaded reports. No private research outcomes
or benchmark labels ship. Scientific scope remains exploratory compatibility with
known amyloid structures, not a probability of amyloid formation or correctness.

Runtime/CDN requests carry normal connection metadata, never selected files.
An Internet connection is needed to load engine assets. Browser caching can reduce
subsequent downloads; fully offline operation is not promised. No per-job server
compute is required. Ordinary website bandwidth/hosting quotas still apply.
No cross-origin isolation or SharedArrayBuffer is required. Use a modern browser
with module workers, WebAssembly, and Web Crypto over HTTPS or localhost.

REPRODUCIBLE BUILDS
Activate Emscripten 4.0.10 in an isolated SDK, then:
python3 scripts/build-amyloid-mmalign.py /path/to/em++
Optional --archive /path/to/source.tar.gz uses a cached archive. Its SHA-256 must
match the pinned source. Build flags, source hashes, and output hashes are recorded
in mmalign/build.json; the upstream license is distributed with the binary.

Then bundle the science package and shared pipeline:
python3 scripts/package-amyloid-device.py /path/to/Amyloid_Candidates
The script reads the pinned commit with git archive, not the package working tree.
It also bundles this website's shared analysis modules. Regenerate engine.json
after changing adapters/shared modules or rebuilding MM-align. Dependency/toolchain
upgrades require numerical revalidation. No npm install step downloads a compiler;
the generated browser artifacts are committed for ordinary website deployments.

OUTPUT
The ZIP includes results.json, original coordinate bytes, per-structure component
outputs, gate reports, portable manifests, source/normalized hashes, chain mapping,
canonical confidence metadata, and runtime/scientific provenance. Batch jobs add
alignment coordinates, directed comparison reports, distance matrices, scored
members, clustering settings/results, representatives, and shortlist eligibility.
SHA256.json covers every archive file except itself. Reports are paired with their
manifest and coordinate bytes using SHA-256 before interactive display.

VALIDATION
npm run test && npm run typecheck && npm run lint && npm run build
TEST_BASE_URL=http://127.0.0.1:3838 npm run test:browser
Native worker: see services/amyloid/README.txt.
Browser tests need network access to the pinned runtime CDN. python3 is used only
by the TEST RUNNER to inspect ZIP files; visitors need no Python installation.
Tests compare PDB/mmCIF descriptor outputs to native fixtures, clustering partitions
on 12 synthetic matrices (noise, ties, duplicates, degenerate pools), and a real
six-structure browser job against native MM-align distances. The latter uses
synthetic chain translations of a public prediction, not experimental or private
benchmark data. Archive checksums, confidence handling, cancellation, failure/retry,
progress, mobile layout, and no-upload assertions are included.
The 125-file limit is checked through actual browser selection, worker startup,
and cancellation. A 21-input single-chain fixture completes all 441 directed
alignments, clustering, and a checksum-verified ZIP, exercising the former
400-alignment ceiling. This is not a full 125-assembly capacity benchmark.
