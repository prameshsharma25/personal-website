SUBSTACK READER ACTIVITY

Published essays with a substackUrl display likes, comments, and restacks below
the article. Local articles without a Substack counterpart and draft previews
do not show this panel. No setup or account credentials are required.

SOURCE AND LIMITATIONS

The server reads the public /api/v1/posts/{slug} JSON endpoint on
prameshsharma.substack.com. This endpoint was verified on November 26, 2026,
but is not an officially documented integration contract. It may change or
reject automated requests. Unavailable counts are never replaced with zero.

Only reaction_count (Likes), comment_count (Comments), and restacks (Restacks)
are published. The response must match both the configured post slug and
canonical URL. We do not add child_comment_count to comment_count, infer views
from reactions, or include website visits in these Substack counts.

Substack total views, email open rates, subscriber growth, and traffic sources
are not included in these public engagement counts. Those are publisher
dashboard metrics. Substack supports exporting the Posts
statistics table as CSV, which can support a separately approved snapshot import:
https://support.substack.com/hc/en-us/articles/5320347155860-A-guide-to-Substack-metrics

REFRESH AND FAILURE BEHAVIOR

The browser calls /api/substack-stats with the local article slug on arrival,
when the tab becomes visible, and hourly while visible. The server only accepts
published local articles with links on the configured publication domain.
Successful results are cached for one hour; concurrent requests are combined
per warm server instance. CDN cache lifetime subtracts the age of an existing
result so it does not extend the normal hourly freshness window.

If refresh fails, a warm server instance can show its last successful result
for up to 24 hours, explicitly labeled and dated. Failed requests retry after
five minutes. An instance with no usable cached result shows unavailable.
Server memory is not persistent across deployments or instance replacement.

Upstream requests use an eight second timeout, reject redirects, accept at
most 2 MiB of JSON, and send no authentication credentials. Raw post bodies,
reader identities, email addresses, and upstream errors are not returned to
the browser. There is no Substack iframe, SDK, or tracking pixel.
