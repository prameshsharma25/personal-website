SUBSTACK RECENT WEB VIEWS

WHAT THE COUNTER MEANS
Linked posts can show Views In The Past 30 Minutes, refreshed about every minute.
These are GA4 screenPageViews for the Substack web version of the article.
Repeat page views count. This is not unique readers or lifetime views and does
not include reading inside email or the Substack app. Collection starts after
setup. Blocking, consent choices, filters, and reporting delays affect counts.
A quiet, successfully queried window can show zero. Missing authorization,
invalid reports, or unmatched titles show unavailable instead. The panel stays
hidden when SUBSTACK_GA4_ENABLED is not true. Likes, comments, and restacks still
work independently, without credentials.

1. CONNECT SUBSTACK TO GOOGLE ANALYTICS
Open https://analytics.google.com/ and create a GA4 property. Add a Web data
stream for https://prameshsharma.substack.com. Use a dedicated stream for this
publication, not a stream shared with your personal website or other domains.
Copy its Measurement ID, which begins G-, into your Substack publication's
Settings > Analytics > Google Analytics Measurement ID, then save.

Record these two numeric identifiers from Google Analytics Admin:
  Property ID: Property Settings > Property Details.
  Stream ID: Data Collection And Modification > Data Streams > your Web stream.
Neither is the G- Measurement ID. The stream's default website URL must be
https://prameshsharma.substack.com for this integration's identity check.
Substack says initial data can take 24 hours to appear. Once collection works,
GA4 realtime reports normally reflect events within seconds, with some delay.

2. AUTHORIZE READING THE COUNTS
In Google Cloud, enable Google Analytics Data API and Google Analytics Admin
API. The Admin API is used only to verify the selected web stream.
You can use your existing Web Application OAuth client from YouTube setup;
retain the same OAuth Playground redirect URI:
https://developers.google.com/oauthplayground

In OAuth Playground's settings, select Use Your Own OAuth Credentials and
enter the client ID and client secret. Use Server Side flow, Offline access,
and Consent Screen prompt. In Step 1 authorize only:
https://www.googleapis.com/auth/analytics.readonly

Sign in with a Google account that has at least Viewer access to the GA4
property. In Step 2, exchange the authorization code for tokens. Copy the
refresh token, not the temporary access token. Save it directly to .env.local
and Vercel, without sharing it in chat or a screenshot. This is a separate
Analytics token; leave your working YouTube environment variables unchanged.
Google OAuth apps left in Testing may issue refresh tokens that expire after
seven days. Follow Google's publishing requirements for your OAuth app before
relying on unattended production refreshes. Revoked tokens require reconnection.

3. CONFIGURE THE WEBSITE
Set these server environment variables locally and in Vercel:

SUBSTACK_GA4_ENABLED=true
SUBSTACK_GA4_PROPERTY_ID=<numeric property ID>
SUBSTACK_GA4_STREAM_ID=<numeric stream ID>
SUBSTACK_GA4_CLIENT_ID=<OAuth client ID>
SUBSTACK_GA4_CLIENT_SECRET=<OAuth client secret>
SUBSTACK_GA4_REFRESH_TOKEN=<Analytics refresh token>

Do not prefix these with NEXT_PUBLIC. .env.local is ignored by Git.
Restart the local website, and redeploy Vercel after changing its variables.
Enabling this option publishes aggregate recent view counts on linked posts.
No visitor identities, locations, search terms, revenue, or raw reports are
returned to the browser. No new tracking script is added to this website.

4. VERIFY THE CONNECTION
Open an article on Substack in a browser with tracking allowed. In Google
Analytics, confirm the event appears in Realtime for the intended stream.
Then open the corresponding article on prameshsharma.com. The Reader Activity
panel should show the recent counter with its check time. It can legitimately
show zero when there are no matching tracked visits in the current window.

For a direct check, open:
/api/substack-views?slug=a-vision-of-the-future
status disabled: the enable flag is off.
status unavailable: check numeric IDs, enabled APIs, property Viewer access,
refresh token scope, and the stream's website URL. A public page or Analytics
request can also be temporarily unavailable. No credential details are exposed.
status available: a verified stream and complete report were read successfully.

TITLE MATCHING AND LIMITS
GA4's Realtime API supports unifiedScreenName (page title), not pagePath or
pageLocation. The server reads each linked public Substack page's actual HTML
title and canonical URL, then queries exact titles within the verified stream
and web platform. Local article titles can differ without affecting matching.
Public title lookups are cached for one hour; a renamed Substack post can take
that long to be remapped. Failed title lookups retry after about a minute.
Do not customize GA4 page_title independently of the Substack document title.
Keep titles unique within the publication: Google combines identical titles.
Duplicate titles among linked posts are refused, but pages outside this site's
catalog with an identical title cannot be distinguished by the Realtime API.
The feature supports up to 200 linked posts and does not scrape private stats.

All linked posts share a cached report for about a minute per warm server
instance. Concurrent requests are combined. The CDN's remaining cache lifetime
is calculated from the original check time. Hidden tabs stop polling and refresh
when visible again. Outages do not retain an old window as current data.
There are no paid dependencies or background cron jobs. Google API quotas and
hosting usage still apply. Disable SUBSTACK_GA4_ENABLED and redeploy to stop
reading/publishing counts; cached counts can remain briefly, up to one minute.
This does not remove tracking configured independently in Substack.
